# Support

## Getting help

1. Read the README, especially the quick start, usage, and limitations.
2. Search existing issues for the same question or symptom.
3. If the problem remains, open an issue using the most relevant template.

Include the project version, Python version, operating system, exact command,
minimal sanitized input, observed output, and expected behavior. Remove secrets,
internal hostnames, file paths, rule names, package inventories, and other
organization-sensitive data before posting.

## Security and conduct reports

Do not open a public issue for a vulnerability, exploit details, leaked data,
or a conduct concern. Follow [SECURITY.md](SECURITY.md) for vulnerabilities and
[CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md) for conduct reports.

## Support policy

Support is provided on a best-effort basis for the latest released minor
version and the current `main` branch. Questions about custom integrations or
environment-specific policy may require community investigation.
